# CLAUDE.md

Guidance for Claude Code in this repository. See `README.md` for features, setup and configuration.

## Rules

- **Changelog on every commit.** Each commit adds its changes to `CHANGELOG.md` in the same commit: a bullet at the top
  of the section for today's date (`## YYYY-MM-DD`, create it above the previous dates if missing). Write in English,
  describe what changed for users or developers, not the files touched. Several related changes can share a bullet
  with sub-bullets.
- **User changelog alongside.** Whenever a commit adds something users notice to `CHANGELOG.md` (new feature,
  fix), it also adds a short, non-technical entry to `apps/web/src/changelog.ts` (the "What's new" page under
  Account): at the top of today's day (create it if missing), `kind` `new` or `fix`, text in German and English
  (`de`/`en`), no file names, endpoints or migrations. Developer-only changes (refactors, tests, docs, CI) get none.
- **Sync is copy and paste only.** pr0game's rules forbid automation: never add code that runs on game pages
  (userscripts, bookmarklets, extensions) or endpoints meant for automated submission. Improvements to syncing stay
  inside the hub (paste, clipboard, file upload).
- **No deployment details.** Server setup, hosts and SSH belong to the private deployment repository. This repository
  only builds the Docker images, publishes them to `ghcr.io/neffez/pr0game-hub` and `ghcr.io/neffez/pr0game-tools`
  (public, `latest` and the commit) and sends the `repository_dispatch` from CI; the deployment pulls the images.
- **Language.** Code, comments, commit messages, README and changelog in English. UI texts live in
  `apps/web/src/locales/de.ts` and `en.ts`; always update both. Texts of push notifications are built by the server and
  live in `apps/server/src/push.ts` (German and English; English is typed against German, so a missing text fails the
  typecheck).
- **OpenAPI with API changes.** The public contract is [`apps/server/openapi.yaml`](apps/server/openapi.yaml)
  (served as `/api/openapi.json` and `.yaml`). Any commit that adds, removes or changes HTTP API behavior—paths,
  methods, auth, query/header parameters, or response shape—must update that file in the same commit so it stays
  accurate (paths, `operationId`s, security, and schemas for affected operations; descriptions in English).
- **Game times are not fixed.** Never assume fixed statistics hours (0, 6, 12, 18 o'clock) or a fixed update
  interval: each server configures them and its clock may ignore daylight saving. Learn them from synced data (e.g.
  `statInterval` in `apps/server/src/repo/syncHints.ts`) or work relative to the synced updates.
- **Personal rules** of a contributor go into `CLAUDE.local.md` (gitignored, loaded in addition to this file).

## Commands

```bash
pnpm install
pnpm --filter "./packages/*" build   # web and server import the built packages
pnpm typecheck
pnpm test
pnpm build
```

## Layout

- `packages/parser` (`@pr0hub/core`): page parsers (cheerio), element data in `src/data/` (generated by `pnpm gen:tech` / `pnpm gen:costs`).
  Ships, defense and missiles are a catalog per universe (`units.ts`: defaults from the generated data, `liveUnits.ts`
  and `@pr0hub/flight`'s drives and cargo; a universe stores only its differences). Code for one universe sets the
  active catalog (web) or passes it (`units` options, `withUnits` around synchronous code on the server).
  Universe settings are one contract in `universe.ts` (`@pr0hub/core/universe`: type, defaults, validation, the
  tools' hash keys and the `uo` unit link value); server, web, admin form and tools import it.
- `packages/flight` (`@pr0hub/flight`): flight math ported from the game's `FleetFunctions` (distance, ship speed,
  duration, consumption, recall), ACS planning (`acs.ts`), retime candidates (`retime.ts`) and interplanetary
  missiles (`missile.ts`: range, flight time, `calculateMIPAttack`); must stay second-exact with the game and the
  flight calculator.
- `packages/loot` (`@pr0hub/loot`): ACS loot settlement (loot shares like the game's `calculateSteal`, covering
  costs, profit split, transfers), used by the loot calculator in `apps/tools` and by the hub; `paste.ts` fills a
  settlement from pasted pages (battle report, messages, empire, marketplace via `@pr0hub/core/messages`) for the tool.
- `packages/battle` (`@pr0hub/battle`): battle simulation on Battlerust, the game's Rust engine as WebAssembly
  (`pnpm build:battle` exports it to `wasm/` via the `battle-wasm` Docker stage): engine input like the game's
  `createRustJson` (`input.ts`), evaluation like `parseRustJson` (`result.ts`), loot (`steal.ts`), runs and summary
  (`simulate.ts`), link format (`share.ts`); unit values from the unit catalog of `@pr0hub/core/units`, engine abilities (stun, shield domes) in `src/live.ts`.
- `packages/planner` (`@pr0hub/planner`): build orders: import of pr0plan exports (`pr0plan.ts`), target levels, done
  steps and the settings check against the hub (`hub.ts`), the timeline from the hub's state (`simulate.ts`, like
  pr0plan's `GameReducer` with storage, synced fleets and production from `@pr0hub/core/production`); used by the
  web app and the server's notifications.
- `apps/server`: Fastify + SQLite; migrations in `migrations/` (numbered SQL files); every game-data query goes through `groupContext` so data stays within its group (`test/groupScope.test.ts` fails on SQL on a group table without `group_id` or a key); OpenAPI spec in `openapi.yaml`. The battle simulator API (`src/battle.ts`, `src/routes/battle.ts`) runs `battle-worker.mjs` (plain JS next to `src/` and `dist/`) in a worker thread; it is the only POST allowed with read-only tokens (route config `allowToken`).
- `apps/tools`: static tools (Vite, no framework): `index.html`, `flight-calculator/` (UI in `main.js`, calculation
  in `src/core.ts` on top of `@pr0hub/flight`), `acs-loot/` (glue in `src/loot.ts` on top of `@pr0hub/loot`) and
  `ipm-calculator/` (glue in `src/missile.ts` on top of `@pr0hub/flight`) and `battle-simulator/` (glue in
  `src/battle.ts` on top of `@pr0hub/battle`, battles in a Web Worker `worker.js`) and `moon-destruction/`
  (calculation in `src/moon.ts`, formulas of the game's `MissionCaseDestruction`); each tool has its UI in `main.js`
  and its texts DE/EN in `i18n.js`. All pages share `shared/tools.css` and `shared/shell.js` (header with language
  switch and share link, texts via `data-t*`, toast, tooltips); tabs of independent calculations (flight calculator,
  battle simulator, loot calculator) are `shared/tabs.js`; the universe settings dialog (fields, hash keys,
  texts, one localStorage key for all tools) is `shared/uni.js`. Own values for ships and defense (one store for all tools, editor with
  pasted game pages, link key `uo`) are `shared/units.js` on top of `@pr0hub/core/units`. Docker target `tools`.
- `apps/web`: Vue 3 SPA; the mobile layout starts below 800 px (`useMobile` in `composables.ts`, same breakpoint in `style.css`).
